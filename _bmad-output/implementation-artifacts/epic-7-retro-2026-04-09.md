# Retrospective — Epic 7: Board Enhancements

## Summary

Epic 7 delivered 2 stories (drag-and-drop task reordering and task search/multi-filter) as the first Phase 2 epic. Two rounds of adversarial code review produced 11 patches and 6 deferred items. The epic completed with 100% story delivery and zero production incidents.

## What Went Well

### Architecture Pattern Reuse
- Phase 1 patterns (optimistic updates, API wrapping, error handling, query key factory) translated directly to new features
- `useUpdateTask` optimistic pattern was the blueprint for `useReorderTask` — no new patterns needed
- TanStack Query + useState state management approach scaled cleanly

### Library Selection
- @dnd-kit was the right choice — PointerSensor with 5px activation distance cleanly separated click from drag
- verticalListSortingStrategy + SortableContext handled the sort UX out of the box
- restrictToVerticalAxis modifier prevented cross-column drag confusion

### Code Review Effectiveness
- Three-layer parallel review (Blind Hunter, Edge Case Hunter, Acceptance Auditor) caught 11 real bugs across 2 stories
- Edge Case Hunter caught the critical `filteredTasks` vs `tasks` position mismatch in 7.1
- Whitespace search bug and drag-with-filters position issue caught in 7.2
- Deduplication across layers confirmed high-signal findings

### Clean Execution
- Story 7.2 was zero-friction after 7.1 stabilized the Docker environment
- Purely frontend story (7.2) required no backend changes — clean scope
- Both stories completed in a single session each

## What Didn't Go Well

### Docker Dev Environment Fragility
- Story 7.1 hit Postgres auth failure from stale volume credentials
- Backend dist/ folder had stale CJS output causing ESM conflict
- `tsx` not found in container due to anonymous volume issues
- Resolution required `docker compose down -v` and rebuild — lost time

### No Test Infrastructure (Carried from Phase 1)
- Still no automated tests after 8 completed epics
- All quality assurance relies on LLM code review — single point of failure
- Phase 1 retro explicitly committed to Playwright + Vitest — not done

### React 19 ESLint Surprises
- `setState` in `useEffect` flagged by strict React hooks rules
- `useRef` access during render flagged
- Required alternative approaches (event-driven reset, ref avoidance)

### Previous Retro Follow-Through
- 4 of 5 Phase 1 retro action items were not addressed
- Test infrastructure, CORS config, TOCTOU fixes, rate limiting — all still pending
- Deferred work backlog grew from 7 to 13 items across this epic
